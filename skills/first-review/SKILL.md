# AI一次レビュー

人間レビューの代替ではなく**前処理**。機械的に検査できるものを先に潰し、人間を設計判断と契約の妥当性に集中させる。

## 検査項目

1. **規約・スタイル**: プロジェクトの規約(CLAUDE.md・lint設定・既存コードの慣習)との不整合。**規約の出所で出し方を分ける**——lint設定にある規約の違反は機械的指摘。**散文にしか無い規約(CLAUDE.md・スキル・地図)の違反**は、指示で守れなかった証拠なので、指摘に加えて**所見**に「散文のみ。構成化の案: <Lint ルール・アーキテクチャテスト等の名前と設定の下書き>」を添える。案が書けないときは添えない。導入は別の小さいPR(既存コードの違反はラチェットで床にする)で、このPRには混ぜない。違反が出ていない規約への先回りの提案はしない
2. **テストと実装の整合**: テストが契約(入出力・失敗時の挙動)を表しているか。アサーションの無いテスト、実装の挙動をなぞっただけのテストを指摘する
3. **Happy Path偏り**: 異常系・境界値のテスト欠落。特に、仕様に失敗時挙動の記述があるのにテストが無い箇所
   - **結合テストの有無**: diff が箱の境界を越える(他の箱の契約を呼ぶ・変える、境界をまたぐ契約を変える)のに結合テストが無い、またはPRのテスト欄の結合テストの行が「対象外」になっている箇所を指摘する。**diff が越えた境界が「固定しなかった境界」に入っている、またはその境界の依存がテストダブルなら、それも指摘する**(境界は固定されていない。不可逆系の境界で実物相当が無い場合と、PRのテスト欄で「仕様書で人が確認した境界」に入っている場合を除く——後者は回帰が固定されていない旨を**所見**に出す)。「未実施(実行手段なし)」と記録されていたら、**リポジトリに実行手段(CI設定・既存の結合テスト・起動スクリプト)が本当に無いかを検査し、あれば指摘する**。無ければそのまま報告する。**出力の置き場**: 欄が「対象外」・越えた境界がダブル・実行手段が実在する、は機械的指摘。境界を越えるかの判定を伴うものと、実物相当か(手製のフェイクは判別できない。判別できなければ「未判定」)は所見
4. **レビュー指定の突き合わせ**: PRの「レビュー指定」とdiffの実態を照合する。不可逆な副作用(スキーマ・データ移行・課金・外部送信・削除)を持つ変更が契約レベル扱いになっていたら警告する
5. **隔離の確認**: 契約レベル指定のコードが安定したインターフェースの後ろに隔離されているか。ドメイン中核に編み込まれていたら警告する
6. **地図との整合**: diffが契約・不変条件・危険領域(地図 `docs/map/<領域>.md` のLevel 1〜3)を変えるかを判定し、変えるのに地図の更新がPRに含まれていなければ指摘する([update-map](../update-map/SKILL.md)で更新できる旨を添える)。**その領域の**地図がまだ存在しない場合は「未検査(地図なし)」と報告し、**[update-map](../update-map/SKILL.md) の初版生成から始められる旨を添える**
7. **設計メモと diff の突き合わせ**(設計メモが辿れる場合): diff に、設計メモの「決めたこと」に無い挙動・分岐・依存の追加があるかを見る。あるのに完了報告の「メモ外の決定」に申告されていなければ、その箇所を**所見**に出す(「申告されていない決定の候補」。判定ではない——設計の範囲内かは著者が仕分ける)。完了報告が辿れなければ「未検査(完了報告なし)」と報告する

## 出力

出力は3ブロックに分け、この順で出す:

1. **BLOCKER(単独枠)**: 検査項目4の不可逆系誤分類警告。**他の指摘と混ぜない**——スタイル指摘の中に埋めると警報疲れで流される。該当なしなら「不可逆系の誤分類: なし(検査済み)」と1行書く
2. **機械的指摘**(重要度順、各指摘に根拠と該当箇所): lint的に判定できたもの(規約違反、アサーション無しテスト等)
3. **所見**(判断の候補であって判定ではない): 「テストが契約を表しているか」「Happy Path偏り」「隔離されているか」など、本来は人間の判断に属するもの。**所見は精読の候補箇所の提示であり、「問題なし」という所見は合格印ではない**ことを明記する

最後に「人間レビューで見るべき箇所」の要約(設計判断・契約の妥当性・構造理解対象のデータフロー・行レベル対象の精読ポイント)を付ける。

## 守ること

- **実装を書いたセッションとは別セッションで実行する。** 同一セッションで実行すると、自分がなぞって書いたテストを自分で検査する自作自演に戻る
- **独立照合([crosscheck](../crosscheck/SKILL.md))の人間版を担当する人には、その人が期待値を書き終えるまでこの出力を渡さないこと。**
- **このスキルは独立照合ではなく、その代わりにもならない**。検査項目7も、著者の仕分け(受け入れ/差し戻し/裁定へ)の代わりにはならない——**著者が仕分けを記録し終えるまでこの出力を渡さない**(先に読むと全件が受け入れに倒れる)
- **承認・マージの判断や推奨はしない。** それはマージした人の責任である。「マージしてよさそうです」の類も書かない
- 指摘の採否は人間が決める。AIレビュー指摘の却下率が高いのは正常な運用である。ただし**BLOCKER枠の警告は「いつもの指摘」と一緒に一括却下される設計にしない**のがこの出力形式の目的である
- 見つからなかった観点は「検査したが指摘なし」と明示する。沈黙と合格を区別できるようにする。ただし「指摘なし」と書けるのは実際にその観点でdiff全体を検査した場合だけ——検査していない観点は「未検査」と書く
