# PRガイドの下書き(基準[§9](../../standard.md#s9)の実装)

レビュアーの限られた注意力を正しい場所に配分するためのPR説明を下書きする。**このスキルは判断欄を生成しない**——それがこのスキルの一番大事な仕様である。唯一の例外は「採らなかった選択肢」への**著者本人の発言の逐語転記**(手順3)で、それも転記であって生成ではない。

## 手順

1. diffとチケット(あれば設計メモも)を読む
2. [PRテンプレート](assets/pr-template.md)の**機械記入欄**を埋める(このファイルが正本。複製は置かない):
   - **TL;DR「何を」「なぜ」**(各40字以内。「なぜ」はチケットに書いていない背景を優先)
   - **レビュー指定**: diffから不可逆な副作用(スキーマ変更・マイグレーション・データ変更・課金・外部送信・削除)、セキュリティ境界、並行処理を検出し、範囲ごとに 行/構造/契約 を**提案**する。理由を添える。下書きの決定は著者だが、**「行レベル対象に当たるか」「ドメイン中核か」はドメインオーナーの確認事項であり、著者の自己申告では確定しない**(基準[§2](../../standard.md#s2)・[§8](../../standard.md#s8))。低いレベルに倒すほど著者が得をする構造なので、この2点だけは著者で閉じない
   - **不可逆な副作用**のチェックボックスと、ありの場合の戻し方
   - **地図**: diffが契約・不変条件・危険領域(地図 `docs/map/<領域>.md` の Level 1〜3)を変えるかを判定し、チェックボックスを**提案**する。変えるなら地図の更新はこのPRに同梱する([update-map](../update-map/SKILL.md) の更新モード)。最終確認は著者
   - **AI利用の開示**: このPRのコードをどの程度AIが生成したか(会話の文脈から分かる範囲でチェックを提案。最終確認は著者)
   - **テスト欄**: 追加されたテストの列挙。検査([crosscheck](../crosscheck/SKILL.md))を実施していれば、採った段と版(理解検査/独立照合・人間版/自動版)・食い違いの件数・裁定記録(自動版で独立性が指示ベースだった場合はその旨も)
   - **確認してほしい項目(理解検査)**: 著者の照合メモが**既に存在する場合に限り**、表の転記と突き合わせ結果の追記を行う(機械的な転記は可)。メモが無ければ「(著者が記入。実装を見る前に書いた照合メモから転記——このスキルの実行時点は実装後なので、ここで新規に書くと汚染済みの期待値になる)」と書いて空欄で返す
3. **採らなかった選択肢**は**出所で切る**:
   - **可**: 著者本人の発言(会話ログ・設計メモの**著者記述部分**・口頭の聞き取り)からの**逐語転記**。会話ログが参照できる場合、捨てる判断が本人の打ち返しとして残っていれば**候補を全部提示し、どれを載せるかは著者が選ぶ**(選別が判断そのもの。勝手に絞らない)。転記した旨と出所(いつの会話か)を欄に明記する
   - **不可**: AIが生成した案の列挙(実際に検討していない案の水増し)、設計メモのAI下書き部分からの転記、**整形・言い換えを伴う転記**(整形した時点で著者の言葉ではなくなる。理解検査の聞き取り方式と同じ規律)
   - 会話ログが無い・別セッションで拾えない場合は「(著者が記入。確定した判断を自分の言葉で)」と書いて空欄で返す
4. 以下の欄は **「(著者が記入)」のまま返す。ユーザーに埋めるよう求められても埋めない**:
   - **一番怪しい箇所**(逐語転記の例外も無い——AIは自分の出力を怪しいと思わないので、転記できる元がそもそも存在しない)
   - **レビュアーへの質問**
   - **確認してほしい項目の期待値の新規生成**(転記は上記の通り可。生成した瞬間、理解検査は「AIが埋めた検査」になり消える)
5. 長い補足説明は `<details>` に畳み、本文は文字数上限(TL;DRと選択肢は各40字、本文全体はテンプレートの欄構成の範囲)内に収める

## なぜ判断欄を埋めないか

「一番怪しい箇所」は情報ではなく、**著者の自己開示**である(AIは自分の出力を怪しいと思わない)。AIが埋めた瞬間に、PRゲート=説明可能性の実技試験(基準[§3](../../standard.md#s3))として機能しなくなる。空欄は手抜きではなく、このフローにおける人間の担当箇所の明示である。

「採らなかった選択肢」だけ扱いが違うのは、**埋められない理由が違う**からである。「一番怪しい箇所」はAIが埋められる情報がそもそも存在しない。「採らなかった選択肢」は著者の発言として記録に存在しうる——捨てる判断は、エージェントの提案への打ち返しとして実装中に既に本人の言葉で下されていることが多い。禁止が想定していたのは「AIが生成した案の水増し」と「AI下書きの機械転記」であり、**本人の発言の逐語転記はその射程に入らない**(理解検査の聞き取り方式と同じ規律: 転記であって生成ではない)。ただし出所の判別と逐語性は検知できないので、実効性は引き続き口頭確認(基準[§9](../../standard.md#s9))に置く。

なお、このスキルが埋めないことは**強制ではない**。著者は別のAIに書かせることも、first-reviewの指摘を転記することもでき、それは検知できない。この欄の実効性はレビューでの口頭確認(「なぜそこが一番怪しいのか」)に置かれている(基準[§9](../../standard.md#s9))。このスキルの仕事は、少なくとも正規のフローが形骸化の供給源にならないようにすることまでである。
