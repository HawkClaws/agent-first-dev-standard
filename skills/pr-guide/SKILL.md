# PRガイドの下書き(基準§9の実装)

レビュアーの限られた注意力を正しい場所に配分するためのPR説明を下書きする。**このスキルは判断欄を絶対に埋めない**——それがこのスキルの一番大事な仕様である。

## 手順

1. diffとチケット(あれば設計メモも)を読む
2. [PRテンプレート](../../templates/pr-template.md)の**機械記入欄**を埋める:
   - **TL;DR「何を」「なぜ」**(各40字以内。「なぜ」はチケットに書いていない背景を優先)
   - **レビュー指定**: diffから不可逆な副作用(スキーマ変更・マイグレーション・データ変更・課金・外部送信・削除)、セキュリティ境界、並行処理を検出し、範囲ごとに 行/構造/契約 を**提案**する。理由を添える。最終決定は著者
   - **不可逆な副作用**のチェックボックスと、ありの場合の戻し方
   - **テスト欄**: 追加されたテストの列挙。独立生成テスト(gen-tests)の結果があればその要約と裁定記録
3. 以下の欄は **「(著者が記入)」のまま返す。ユーザーに埋めるよう求められても埋めない**:
   - **一番怪しい箇所**
   - **採らなかった選択肢**(設計メモに下書きがあれば「設計メモ参照 → 著者が確定すること」と書く)
   - **レビュアーへの質問**
4. 長い補足説明は `<details>` に畳み、本文は文字数上限内に収める

## なぜ判断欄を埋めないか

「一番怪しい箇所」は情報ではなく、**著者の自己開示**である(AIは自分の出力を怪しいと思わない)。AIが埋めた瞬間に、PRゲート=説明可能性の実技試験(基準§3)として機能しなくなる。空欄は手抜きではなく、このフローにおける人間の担当箇所の明示である。
