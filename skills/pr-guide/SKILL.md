# PRガイドの下書き(基準§9の実装)

レビュアーの限られた注意力を正しい場所に配分するためのPR説明を下書きする。**このスキルは判断欄を絶対に埋めない**——それがこのスキルの一番大事な仕様である。

## 手順

1. diffとチケット(あれば設計メモも)を読む
2. [PRテンプレート](assets/pr-template.md)の**機械記入欄**を埋める(このファイルが正本。複製は置かない):
   - **TL;DR「何を」「なぜ」**(各40字以内。「なぜ」はチケットに書いていない背景を優先)
   - **レビュー指定**: diffから不可逆な副作用(スキーマ変更・マイグレーション・データ変更・課金・外部送信・削除)、セキュリティ境界、並行処理を検出し、範囲ごとに 行/構造/契約 を**提案**する。理由を添える。下書きの決定は著者だが、**「行レベル対象に当たるか」「ドメイン中核か」はドメインオーナーの確認事項であり、著者の自己申告では確定しない**(基準§2・§8)。低いレベルに倒すほど著者が得をする構造なので、この2点だけは著者で閉じない
   - **不可逆な副作用**のチェックボックスと、ありの場合の戻し方
   - **地図**: diffが契約・不変条件・危険領域(地図 `docs/map.md` の Level 1〜3)を変えるかを判定し、チェックボックスを**提案**する。変えるなら地図の更新はこのPRに同梱する([update-map](../update-map/SKILL.md) の更新モード)。最終確認は著者
   - **AI利用の開示**: このPRのコードをどの程度AIが生成したか(会話の文脈から分かる範囲でチェックを提案。最終確認は著者)
   - **テスト欄**: 追加されたテストの列挙。独立照合(crosscheck)を実施していれば、採った版(人間版/自動版)・食い違いの件数・裁定記録(自動版で独立性が指示ベースだった場合はその旨も)
3. 以下の欄は **「(著者が記入)」のまま返す。ユーザーに埋めるよう求められても埋めない**:
   - **一番怪しい箇所**
   - **採らなかった選択肢**(設計メモに下書きがあっても**転記しない**。「(著者が記入。設計メモの下書きの転記ではなく、確定した判断を自分の言葉で)」と書く)
   - **レビュアーへの質問**
4. 長い補足説明は `<details>` に畳み、本文は文字数上限(TL;DRと選択肢は各40字、本文全体はテンプレートの欄構成の範囲)内に収める

## なぜ判断欄を埋めないか

「一番怪しい箇所」は情報ではなく、**著者の自己開示**である(AIは自分の出力を怪しいと思わない)。AIが埋めた瞬間に、PRゲート=説明可能性の実技試験(基準§3)として機能しなくなる。空欄は手抜きではなく、このフローにおける人間の担当箇所の明示である。

なお、このスキルが埋めないことは**強制ではない**。著者は別のAIに書かせることも、first-reviewの指摘を転記することもでき、それは検知できない。この欄の実効性はレビューでの口頭確認(「なぜそこが一番怪しいのか」)に置かれている(基準§9)。このスキルの仕事は、少なくとも正規のフローが形骸化の供給源にならないようにすることまでである。
