## 2. 実装(検査の盲検フェーズと**並列**に進める)

**委譲が先、期待値が後**(flow「セッションの分離」)。逆順になったら「独立性は指示ベース」と記録。

- [ ] 検査の段と版の判定 — crosscheck 手順0(標準=理解検査。**不可逆系は独立照合必須**。第二解釈者がいなければ自動版)
- [ ] 実装の委譲 — サブエージェント(別セッション)へ。**完了を待たずに次へ進む**
      *委譲プロンプトはチケットと承認済み設計メモの所在だけ。照合メモの内容もパスも含めない。
      完了報告に「迷った箇所・仕様が薄く補完した箇所」を残させる(§9)*
- [ ] 👤 **理解検査:期待値の書き出し(著者)** — crosscheck 手順U ※標準。実装の実行中に並列で
      *直接編集か、メインセッションの聞き取り。照合メモはリポジトリの外。エージェントに埋めさせない(crosscheck 手順U)*
- [ ] 独立照合の材料を切り出して提示 — crosscheck 手順A-1・A-2 ※独立照合をやる場合のみ
      *実装・テスト・first-review の出力を含めない。この時点ではまだ存在しない*
- [ ] 👤 **独立照合:期待値の書き出し(第二解釈者)** — **実装方針を書いていない人**(レビュアー。不可逆系はドメインオーナー)※独立照合をやる場合のみ

- [ ] 実装の完了確認 — サブエージェントの結果を受け取る
- [ ] 自動版の実行 — crosscheck 手順B ※判定が自動版のときだけ

## 3. PR作成(地図に触るのはここだけ)

- [ ] 👤 **この変更が触る領域を決める** — ドメインオーナーの担当単位(§8)
      *どう切っても検収先・境界の持ち主が変わらない場合(一人運用など)は機械が決めて「機械が決めた」を記録し、人が見て止める(§7)。切り方の手掛かりは§11*
- [ ] その領域の地図が無ければ初版生成 — update-map モード1 ※**領域ごとに一度だけ**
      *このPRに同梱する。「スコープ外なので別途起票」に逃さない(§12 手順2)*
- [ ] 👤 **地図の初版を検収** — その領域のドメインオーナー ※初版を作った場合のみ
      *最低ライン: Level 2・3 の通読・修正。reviewed を書くのは人間だけ(update-map モード1)。済むまでこの領域のマージゲートの地図要件は発効しない*
- [ ] 理解検査の突き合わせと結果の反映 — crosscheck 手順U-4・U-5 ※理解検査の場合
      *A(仕様が2通りに読めた)→「確認してほしい項目」欄へ。B(知らなかった)→コメント・地図へ反映(PRには差分だけ)。記録はテスト欄1行*
- [ ] 出力との突き合わせ — 実データを1本通し、分布と代表的な集計(分母明示)を出す。現れなかった値も記録 ※計測・集計・エクスポート系のみ(§4)
- [ ] PR下書きの機械記入欄 — pr-guide ※突き合わせの後(件数・実施記録を欄に書くため)
      *「一番怪しい箇所」は転記で埋まる(実装側の申告+設計メモの懸念点)。著者は見て、違うものを消すだけ(§9)*
- [ ] 地図の更新をPRに同梱 — update-map モード2 ※契約等を変える場合
- [ ] 👤 **採らなかった選択肢の選別** — 著者
      *候補は pr-guide が会話ログから転記済み(可否を聞かない)。著者は載せるものを選ぶ(§9)*
- [ ] AI一次レビュー — first-review(実装とは別セッション)
