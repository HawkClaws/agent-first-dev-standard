## 1. 着手

- [ ] 設計メモの「契約」欄の下書き — design-memo ※契約・不変条件・危険領域を変える場合のみ(独立照合の材料。**地図はここでは触らない**)
- [ ] 👤 **設計メモへの合意** — チーム。**不可逆系ならドメインオーナーの明示承認**
      *不可逆系では「期限まで無返事なら進む」を使わない*

## 2. 実装(検査の盲検フェーズと**並列**に進める)

**実装の完了を待たない。** 材料の提示と期待値の書き出しは、実装が始まる前か進行中にやる。理由は2つ:
①クリティカルパスに乗らない(実測で0分。実装3分45秒と並列に終わった)
②**実装ファイルがまだ存在しないので、隔離が指示ではなく構成で保証される**。
実装後に回すと、書き手がPRや first-review の出力を開いた時点で汚染される(§4)。

- [ ] 検査の段と版の判定 — crosscheck 手順0(標準=理解検査。**不可逆系は独立照合必須**)
- [ ] 👤 **理解検査:期待値の書き出し(著者)** — crosscheck 手順U ※標準
      *直接編集か、エージェントの聞き取り(1問ずつ質問し答えをそのまま書き留める)。実装の出力を見る前に書く。
      書いた期待値は実装エージェントに渡さない(渡すと一致がトートロジーになる)。
      エージェントに埋めさせた時点で検査は消える。書けない欄=理解不足か仕様の曖昧さのシグナル*
- [ ] 独立照合の材料を切り出して提示 — crosscheck 手順A-1・A-2 ※独立照合をやる場合のみ
      *実装・テスト・first-review の出力を含めない。この時点ではまだ存在しない*
- [ ] 👤 **独立照合:期待値の書き出し(第二解釈者)** — **実装方針を書いていない人**(レビュアー。不可逆系はドメインオーナー)※独立照合をやる場合のみ
      *実装と並行して書ける。著者が書くと、実施記録の付いた自己照合になる(その場合は理解検査として記録)*
- [ ] 実装(エージェントに委譲)※上の期待値の書き出しと並列でよい
- [ ] 自動版の実行 — crosscheck 手順B ※判定が自動版のときだけ

## 3. PR作成(地図に触るのはここだけ)

- [ ] 👤 **この変更が触る領域を決める** — ドメインオーナーの担当単位(§8)
      *領域の切り方が、地図の検収先・マージゲートの発効単位・境界をまたぐ契約の持ち主を決める。機械には決められない。
      領域が1つのプロジェクトなら領域名はリポジトリ名かサービス名でよい*
- [ ] その領域の地図が無ければ初版生成 — update-map モード1 ※**領域ごとに一度だけ**
- [ ] 👤 **地図の初版を通読・修正して検収** — その領域のドメインオーナー ※初版を作った場合のみ
      *無修正の受け入れは読まれていない疑い。これが済むまでこの領域のマージゲートの地図要件は発効しない*
- [ ] PR下書きの機械記入欄 — pr-guide
- [ ] 理解検査の突き合わせと「確認してほしい項目」欄への転記 — crosscheck 手順U-4・U-5 ※理解検査の場合
- [ ] 地図の更新をPRに同梱 — update-map モード2 ※契約等を変える場合
- [ ] 👤 **一番怪しい箇所** — 著者
- [ ] 👤 **採らなかった選択肢** — 著者(設計メモからの転記ではなく、確定した判断を自分の言葉で)
- [ ] AI一次レビュー — first-review(実装とは別セッション)

## 4. レビュー

期待値は§2で実装と並列に書かれている。**まだ書かれていないなら、PRの差分・テスト・first-review の出力を開く前に書く。** 開いた後では検査は成立しない(基準§4)。

- [ ] 突き合わせ — crosscheck 手順A-4 ※独立照合の場合(理解検査の突き合わせは§3で済んでいる)
- [ ] 👤 **食い違いの裁定** — 仕様の持ち主。不可逆系はドメインオーナー同席
- [ ] 裁定の書き戻し — **3箇所すべて**(基準§4): ①仕様/設計メモ ②**裁定前に書かれたテスト** ③地図 Level 1〜2(契約を変えた場合)
- [ ] 👤 **理解レベルの確定**(行レベル該当か・ドメイン中核か) — ドメインオーナー
