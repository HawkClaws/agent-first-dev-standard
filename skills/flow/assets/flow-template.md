## 2. 実装(検査の盲検フェーズと**並列**に進める)

**委譲が先、期待値が後。** 実装の委譲プロンプトを書いた時点で期待値がまだ存在しなければ、
「期待値をエージェントに渡さない」が指示ではなく構成で保証される(§4。逆順になったら「独立性は指示ベース」と記録)。
聞き取りができるのは人間と対話できるメインセッションだけなので、実装はサブエージェントに委譲する(flow「セッションの分離」)。
これで実装と期待値の書き出しが並列に進み、クリティカルパスに乗らない(実測で0分)。

- [ ] 検査の段と版の判定 — crosscheck 手順0(標準=理解検査。**不可逆系は独立照合必須**)
- [ ] 実装の委譲 — サブエージェント(別セッション)へ。**完了を待たずに次へ進む**
      *委譲プロンプトはチケットと承認済み設計メモの所在だけ。照合メモの内容もパスも含めない。
      完了報告に「迷った箇所・仕様が薄く補完した箇所」を残させる(「一番怪しい箇所」の申告の転記元。§9)*
- [ ] 👤 **理解検査:期待値の書き出し(著者)** — crosscheck 手順U ※標準。実装の実行中に並列で
      *直接編集か、メインセッションによる聞き取り(1問ずつ質問し答えをそのまま書き留める)。
      照合メモは**リポジトリの外**に置く。エージェントに埋めさせた時点で検査は消える。
      書けない欄=理解不足か仕様の曖昧さのシグナル*
- [ ] 独立照合の材料を切り出して提示 — crosscheck 手順A-1・A-2 ※独立照合をやる場合のみ
      *実装・テスト・first-review の出力を含めない。この時点ではまだ存在しない*
- [ ] 👤 **独立照合:期待値の書き出し(第二解釈者)** — **実装方針を書いていない人**(レビュアー。不可逆系はドメインオーナー)※独立照合をやる場合のみ
      *実装と並行して書ける。著者が書くと、実施記録の付いた自己照合になる(その場合は理解検査として記録)*
- [ ] 実装の完了確認 — サブエージェントの結果を受け取る
- [ ] 自動版の実行 — crosscheck 手順B ※判定が自動版のときだけ

## 3. PR作成(地図に触るのはここだけ)

- [ ] 👤 **この変更が触る領域を決める** — ドメインオーナーの担当単位(§8)
      *領域の切り方が、地図の検収先・マージゲートの発効単位・境界をまたぐ契約の持ち主を決める。
      どう切ってもそれらが変わらない場合(一人運用など)は、機械が決めて根拠と「機械が決めた」を記録し、人はそれを見て止める(§7)。
      「同じファイルを触るから同じ領域」では切らない(§11)。領域が1つのプロジェクトなら領域名はリポジトリ名かサービス名でよい*
- [ ] その領域の地図が無ければ初版生成 — update-map モード1 ※**領域ごとに一度だけ**
      *このPRに同梱する。「スコープ外なので別途起票」に逃さない(§12 手順2)*
- [ ] 👤 **地図の初版を検収** — その領域のドメインオーナー ※初版を作った場合のみ
      *最低ライン: Level 2(不変条件)・Level 3(危険領域)の通読・修正。別セッションの機械検証(誤り/疑わしい/確認済み)を
      前処理に使ってよいが、reviewed を書くのは人間だけ。無修正の受け入れは読まれていない疑い。
      これが済むまでこの領域のマージゲートの地図要件は発効しない*
- [ ] 理解検査の突き合わせと結果の反映 — crosscheck 手順U-4・U-5 ※理解検査の場合
      *A(仕様が2通りに読めた)→「確認してほしい項目」欄へ。B(知らなかった)→コメント・地図へ反映(PRには差分だけ)。記録はテスト欄1行*
- [ ] 出力との突き合わせ — 実データを1本通し、分布と代表的な集計(分母明示)を出す。現れなかった値も記録 ※計測・集計・エクスポート系のみ(§4)
- [ ] PR下書きの機械記入欄 — pr-guide ※突き合わせの後(件数・実施記録を欄に書くため)
- [ ] 地図の更新をPRに同梱 — update-map モード2 ※契約等を変える場合
- [ ] 👤 **一番怪しい箇所** — 著者が確定
      *実装セッションの申告(迷った箇所・補完した箇所)の転記を下書きにしてよい(「実装側の申告」と明記)。
      残すか・書き換えるかは著者。「なぜそこが一番怪しいのか」に自分の言葉で答えられること(§9)*
- [ ] 👤 **採らなかった選択肢の選別** — 著者
      *候補の転記は機械の仕事——pr-guide が会話ログから可否を聞かずに全部転記して提示する。著者は載せるものを選ぶだけ。
      出所を明記。AI生成案の列挙・AI下書きの転記・整形や言い換えは不可(§9)*
- [ ] AI一次レビュー — first-review(実装とは別セッション)

## 4. レビュー

期待値は上の「2. 実装」の段で実装と並列に書かれている。**まだ書かれていないなら、PRの差分・テスト・first-review の出力を開く前に書く。** 開いた後では検査は成立しない(基準§4)。

- [ ] 突き合わせ — crosscheck 手順A-4 ※独立照合の場合(理解検査の突き合わせは§3で済んでいる)
- [ ] 👤 **食い違いの裁定** — 仕様の持ち主。不可逆系はドメインオーナー同席
- [ ] 裁定の書き戻し — **3箇所すべて**(基準§4): ①仕様/設計メモ ②**裁定前に書かれたテスト** ③地図 Level 1〜2(契約を変えた場合)
- [ ] 👤 **理解レベルの確定**(行レベル該当か・ドメイン中核か) — ドメインオーナー
